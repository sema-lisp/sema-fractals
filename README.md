Generative art made with Sema: fractal experiments and periodic 3D animations. The repository contains the Sema source, reusable rendering tools, PNG/SVG stills, GIF previews, MP4 renders, and verification results.

These four are six-second parametric animations at 1920×1920 and 60 fps, with 3840×3840 supersampling and bloom. GIF previews run at 20 fps.

```sh
git clone https://github.com/sema-lisp/sema-fractals.git
cd sema-fractals/evolving-scenes
sema --no-llm animate.sema        # Kinetic Loom
sema --no-llm animate-three.sema  # Wave Atlas, Comet Ballet, Prism Engine
```

Requires Sema 1.37.0, rsvg-convert (librsvg), and FFmpeg/ffprobe on PATH. On macOS: `brew install helgesverre/tap/sema-lang librsvg ffmpeg`. Rendering full-resolution bloom is computationally expensive.

Earlier scripts that write files use paths relative to the working directory; run them from their own directory. The current Sema pipeline uses no Python. Archived Python tools are kept in legacy-tools/ for provenance.

## Setup and usage

Install the tools on macOS:

```sh
brew install helgesverre/tap/sema-lang librsvg ffmpeg
sema --version
rsvg-convert --version
ffmpeg -version
```

On other systems, install [Sema](https://github.com/sema-lisp/sema#installation), librsvg's `rsvg-convert`, and FFmpeg with H.264 encoding support. All tools must be on PATH. These scripts run with `--no-llm`; no API key is needed.

From a cloned repository, choose a scene:

```sh
cd evolving-scenes
sema --no-llm render.sema              # one Kinetic Loom still
sema --no-llm animate.sema             # full Kinetic Loom video + GIF
cd wave-atlas                         # or comet-ballet / prism-engine
sema --no-llm render.sema              # one still of this scene
sema --no-llm animate.sema             # this scene's video + GIF
```

Each renderer writes its outputs into its working directory. Run scripts from the directory shown; relative library paths depend on it. `prepare-three.sema`, run from `evolving-scenes/`, refreshes the three child directories from the parent scene templates.

Full videos contain 360 independently generated frames; source endpoints are checked for equality before rendering. GIFs repeat indefinitely. MP4 files need repeat enabled in your player. GIF previews have fewer frames and a smaller resolution than the MP4s.

Full-resolution bloom can take tens of minutes. `animate-three.sema` runs three processes concurrently and uses more CPU and memory; use the individual commands for lower peak resource use. Progress and encoder messages go to `render.log` and `encode.log`; completed checks are recorded in `verification.json`. Generated bytecode and runtime logs are ignored by Git.

Geometry, SVG batching, bloom definitions, orchestration, and verification are written in Sema. The native rasterizer and codecs are external tools. The optional `raster-bloom.sema` is an experiment, not the renderer used for the committed videos.

## Finished animations

The high-resolution files are in `memory-fractals/`:

- `address-lace-1920-60fps-loop.mp4`
- `signed-braid-1920-60fps-loop.mp4`
- `phase-coral-1920-60fps-loop.mp4`

Each contains a four-second cycle at **1920 × 1920, 60 fps**. Every frame has independently generated geometry; frames are not interpolated or duplicated to increase the frame rate. Matching `*-bloom-preview.gif` files repeat automatically at 20 fps. Set repeat in your video player to loop the MP4s.

The renderer draws at 3840 × 3840 before Lanczos downsampling. Three Gaussian blur scales produce bloom in linear RGB. The camera stays fixed. Sema checks identical cycle endpoints, changing geometry, valid coordinates, frame counts, output resolution, and frame rate. `*-sema-verification.json` records completed checks.

## Sema implementation

All custom code in the current pipeline is Sema:

- `prepare-native.sema`: creates the animated geometry library from the original recursive constructions.
- `animated-geometry.sema`: parameterized recursive constructions.
- `svg-canvas.sema`: mutable path buffers, SVG batching, palette, bounds checks, and bloom definitions.
- `render-native.sema`: periodic timing, per-frame geometry, PNG generation, binary stdout, and progress reporting.
- `build-native.sema`: bundles the libraries and compiles the tool to Sema bytecode.
- `animate.sema`: runs three independent pipelines concurrently using Sema async tasks, encodes GIF previews, and verifies MP4s.
- `stress-native.sema`: deeper recursion benchmarks, with no rasterizer involved.
- `verify-media.sema`: full video decode checks and direct GIF header/loop inspection using Sema bytevectors.

Native tools provide image rasterization and video codecs: `rsvg-convert`, `ffmpeg`, and `ffprobe`. The current pipeline does not use Python. Only a current SVG and PNG per animation are written temporarily; full-resolution frames stream directly into FFmpeg.

## Reproduce

Requires Sema 1.37.0, rsvg-convert, and FFmpeg with H.264 encoding support.

```sh
cd sema-fractals/memory-fractals
sema --no-llm prepare-native.sema
sema --no-llm build-native.sema
sema --no-llm animate.sema
```

Render one construction or a longer cycle:

```sh
FRACTAL_NAME=signed-braid FRACTAL_FRAMES=480 sema --no-llm animate.sema
```

The frame rate remains 60 fps; 480 frames produce eight seconds. To generate only a high-resolution still:

```sh
FRACTAL_NAME=phase-coral FRACTAL_MODE=preview sema --no-llm native-tool.semac
```

Run geometry stress checks:

```sh
sema --no-llm stress-native.sema
```

## Evolving scenes

`evolving-scenes/` contains the four showcase scenes, including Kinetic Loom: a non-fractal, six-second, 1920-square, 60-fps ribbon animation with bloom. See its README for the Sema source and reproduction commands.

## Earlier experiments

julia.sema and julia.png contain the first Julia-set experiment. splash-fractals/ contains the earlier escape-time constructions, images, and animations. Legacy Python helpers from the earlier experiments are archived in legacy-tools/; they are not used by the current pipeline.

Stored images are PNGs or SVGs; videos are MP4s or GIFs. The earlier pixel-based sources emit PPM intermediates. Those stored intermediates have been converted to PNG and removed.

The constructions are custom experiments. Mathematical novelty is not established. See memory-fractals/notes.md for the rules and related work.
